# jh-media-helper 预览缓存设计

## 1. 背景

当前“音视频混合”Tab 中的预览链路有两个明显特征：

- 输入视频音轨试听：每次点击都会调用 ffmpeg，将指定音轨提取为临时 `aac` 后再交给 `QMediaPlayer` 播放。
- 试听混合：每次点击都会先提取一次原始音轨，再生成一次 5 秒混音预览文件，然后播放。

这套方案在功能上可行，但同一会话内重复点击相同内容时，会反复启动 ffmpeg 和重复写临时文件，预览延迟偏高，资源使用也不经济。

本设计只解决一个问题：**在单次 app 运行期间复用预览产物，避免重复提取/重复混音。**

## 2. 目标与非目标

### 2.1 目标

- 为“输入音轨试听”和“试听混合”提供会话级缓存。
- 缓存目录位于 `~/.jh-media-helper/cache/preview/<session_id>/`。
- 同一会话内，相同预览请求命中缓存时直接播放，无需再次执行 ffmpeg。
- app 退出后清理当前 session 缓存；下次启动不复用旧缓存。
- app 启动时顺带清理旧的 preview session 残留目录。

### 2.2 非目标

- 不做跨重启缓存复用。
- 不做缓存大小限制或 LRU。
- 不做后台预热。
- 不新增缓存管理 UI。
- 不改变当前使用 ffmpeg 生成预览音频的总体方案。

## 3. 方案概览

采用“数据目录下的会话缓存”方案：

- 统一使用已有数据目录 `~/.jh-media-helper`。
- 在其下创建 `cache/preview/` 作为预览缓存根目录。
- 每次 app 启动时创建一个新的 `session_id` 子目录。
- 所有预览产物都放到当前 session 目录中。
- 所有缓存文件名使用 hash，而不是原始路径拼接，避免路径字符问题并保持命名稳定。

## 4. 模块职责

### 4.1 数据目录与 session 管理

新增一组 preview cache 相关路径接口，职责如下：

- 返回 preview cache 根目录路径。
- 创建当前 session 目录。
- 清理旧 session 目录。
- 清理当前 session 目录。
- 按缓存 key 生成当前 session 下的目标文件路径。

这层只管理路径和目录生命周期，不负责 ffmpeg 或播放器逻辑。

建议放在以下两种位置之一：

- 优先：继续放在 `src/core/data_dir.py`，保持数据目录能力集中。
- 备选：新建一个很小的 `src/core/preview_cache.py`，由其调用 `data_dir` 获取根目录。

推荐优先方案是新建 `preview_cache.py`，避免 `data_dir.py` 逐渐承担太多缓存策略细节。

### 4.2 输入音轨试听

`AudioPlayerBar` 负责“输入音轨试听”的缓存命中与写入：

- 输入：`input_path + audio_position`
- 先基于这两个字段计算 key。
- 如果缓存文件已存在，直接 `play_file()`。
- 如果缓存文件不存在，再调用 ffmpeg 提取并写入缓存文件，然后播放。

这样同一会话内，重复点击同一输入音轨时只会提取一次。

### 4.3 试听混合

`CombatAudioPanel.preview_mix()` 负责“试听混合”的缓存命中与写入：

- 混音预览 key：`input_path + audio_position + bg_path + volume`
- 若命中缓存，直接播放缓存的混音结果。
- 若未命中，则生成后写入缓存并播放。

另外，原始音轨提取产物也应单独缓存：

- 原音提取 key：`input_path + audio_position`
- 试听混合先尝试命中原音缓存。
- 只有原音缓存不存在时才调用 ffmpeg 重新提取。

这能避免“相同输入音轨 + 不同背景音乐”场景下反复做 base audio 提取。

## 5. Key 与文件命名

### 5.1 Key 语义

建议使用稳定字符串作为 hash 输入：

- 输入音轨试听：
  - `kind=input_track`
  - `input_path`
  - `audio_position`
  - `version=v1`

- 原音提取缓存：
  - `kind=base_audio`
  - `input_path`
  - `audio_position`
  - `version=v1`

- 试听混合缓存：
  - `kind=mix_preview`
  - `input_path`
  - `audio_position`
  - `bg_path`
  - `volume`
  - `version=v1`

引入 `version` 字段，是为了未来若编码参数、时长或混音逻辑变化，可以通过升级版本号整体失效旧 key，而不必写复杂迁移。

### 5.2 文件命名

缓存文件名统一为：

- `<sha256>.aac`

不在文件名中混入原始路径、音轨编号或业务名，避免：

- 路径字符不安全
- 文件名过长
- 同一逻辑在不同平台下表现不一致

## 6. 生命周期

### 6.1 启动时

主窗口初始化时：

- 确保 `~/.jh-media-helper/cache/preview/` 存在。
- 删除历史 session 目录。
- 创建本次运行的 `session_id` 目录。

### 6.2 运行时

- 各预览调用仅读写当前 session 目录。
- 不主动做按输入文件切换的缓存清理。
- 通过 key 自然区分不同输入、音轨、背景音乐和音量。

### 6.3 退出时

主窗口关闭时：

- 删除当前 `session_id` 目录。

这样可以保证：

- 当前会话内可复用
- 重启 app 后不会复用
- 数据目录中不会长期堆积预览垃圾文件

## 7. 错误处理

- 命中缓存但文件不可读时，视为缓存失效，删除该缓存文件并回退到重新生成。
- ffmpeg 生成失败时，沿用当前已实现的显式报错逻辑，向用户展示失败信息。
- 若缓存目录创建失败，应回退为“无缓存模式”，不阻断预览主流程，但需要记录清晰错误信息给 UI 或日志。

## 8. 测试策略

至少覆盖以下场景：

- 同一会话内，相同输入音轨第二次播放直接命中缓存，不再调用 ffmpeg。
- 同一会话内，相同试听混合第二次播放直接命中缓存，不再调用 ffmpeg。
- 相同输入音轨切换不同背景音乐时，base audio 可复用，但 mix preview 重新生成。
- app 启动时清理旧 session。
- app 退出时清理当前 session。
- 缓存文件丢失或损坏时，可以自动回退到重新生成。

## 9. 实施边界

本次实现建议只覆盖“音视频混合”Tab 内的预览路径：

- 输入音轨试听
- 试听混合

不扩展到批量导出、正式处理流程或未来其他 Tab 的媒体预览功能。

这样范围清晰，便于快速验证收益，也不会把“预览缓存”演变成一个过度泛化的媒体缓存系统。
