# 音视频混合增强设计：mkvmerge、副视频、多 part 输出

## 背景

当前音视频混合功能支持选择一个主视频或音频、一个背景音乐目录，并按背景音乐顺序生成混音音轨或封装 MKV。`v0.1.5` 已修复非封装输出目录、MKV 元数据清理、MKV 时间戳处理、背景音乐排序同步等问题。

本次增强继续围绕音视频混合场景，目标是提升 MKV 封装可靠性、输出文件可读性，并支持将同一组主视频混音结果封装到多个视频 part 中。

## 目标

1. 支持配置和自动检测 `mkvmerge`，封装 MKV 时优先使用 `mkvmerge`，不可用时回退 FFmpeg。
2. 非封装 `.aac` 输出文件名带背景音乐原文件名，便于回溯来源。
3. 支持在封装 MKV 时添加任意数量副视频，输出 `part1...partN`。
4. 副视频只参与封装，不参与混音；混音音轨只按主视频生成一次。
5. 保持现有音视频混合面板，不新增独立功能页。

## 非目标

1. 不做精确 ffprobe 时长校验，尤其不对裸 AAC 时长做强校验。
2. 不强制用户必须安装 `mkvmerge`。
3. 不为每个副视频重新混音或按副视频时长重采样。
4. 不支持副视频目录自动扫描；副视频由用户逐个添加和排序。
5. 不在本次新增“是否保留原音”的独立用户选项，沿用当前“封装时保留当前视频原始音轨”的行为。

## 配置设计

扩展 `CombatAudioConfig`：

```python
secondary_video_paths: list[str]
mkvmerge_path: str | None
mux_backend: str  # auto / mkvmerge / ffmpeg
```

- `secondary_video_paths` 保存副视频路径，顺序决定 `part2...partN` 输出顺序。
- `mkvmerge_path` 是入队时从全局设置读取的路径快照，保证队列任务执行时行为稳定。
- `mux_backend` 默认使用 `auto`。本次界面只暴露自动模式：优先 `mkvmerge`，不可用回退 FFmpeg。字段保留是为了后续扩展强制后端，不在本次 UI 中开放。

扩展全局设置文件 `settings.json`：

```json
{
  "mkvmerge_path": ""
}
```

工具解析顺序：

1. 如果用户手动配置了 `mkvmerge_path` 且文件存在、可执行，则使用该路径。
2. 否则从 `PATH` 自动检测 `mkvmerge`。
3. 如果检测不到，则回退 FFmpeg 封装。

## UI 设计

### 音视频混合面板

继续在现有“音视频混合”面板内扩展。

左上输入区：

1. 输入视频/音频。
2. 音频目录。
3. 副视频分组。

副视频分组：

- 标题：`副视频（仅封装 MKV 时可用）`。
- 仅当主输入是视频且勾选“封装为 MKV”时启用。
- 未启用时灰显，并保留用户已经添加的列表内容。
- 未封装 MKV 时副视频列表被忽略，不参与校验，不报错。
- 分组内使用紧凑列表，不使用大表格：
  - 每行显示序号、文件名、上移、下移、移除。
  - 底部提供 `添加副视频`、`清空`。
- 顺序由上移/下移按钮维护，避免依赖 Qt 表格视觉行拖拽。

右上输出设置区：

- 保留 `封装为 MKV` 和 `输出目录`。
- 增加只读状态文案：`封装工具：mkvmerge` 或 `封装工具：FFmpeg`。
- 路径选择不放在任务面板内，避免任务面板承载系统级设置。

### 设置页

在现有“设置”选项卡新增 `外部工具` 分组：

- `mkvmerge 路径` 输入框。
- `自动检测` 按钮。
- `选择...` 按钮。
- 状态文案：
  - `已检测：/path/to/mkvmerge`
  - `路径不可用，将自动检测`
  - `未检测到 mkvmerge，将回退 FFmpeg`

设置页保存用户手动路径到 `settings.json`。任务入队时读取当前设置并写入任务配置快照。

## 处理流程

1. 用户选择主视频、音频目录、背景音乐顺序、输出目录、副视频列表。
2. 以主视频时长为基准，对每条背景音乐裁剪或循环。
3. 如果启用混音：
   - 提取主视频选中的音轨。
   - 用主视频选中音轨与每条背景音乐生成最终混音音轨。
4. 如果未启用混音：
   - 使用对齐后的背景音乐作为最终音轨。
5. 如果未封装 MKV：
   - 忽略副视频。
   - 导出 `.aac`。
6. 如果封装 MKV：
   - 构造视频列表：`[主视频] + secondary_video_paths`。
   - 对每个视频执行一次封装。
   - 每个 MKV 都使用同一组最终音轨。
   - 每个 MKV 都保留当前被封装视频自己的原始音轨，放在最终音轨后面。
   - 第一条最终音轨设为默认音轨。
   - 优先使用 `mkvmerge`，不可用时回退 FFmpeg。

副视频时长策略：

- 最终音轨只按主视频时长生成一次。
- 副视频更长时不额外补音轨；副视频更短时由播放器按视频自然结束。
- 不因副视频时长差异报错。

## 输出命名

所有输出使用同一个批次时间戳。

### 非封装输出

混音模式：

```text
主视频名_mixed_YYYYMMDDHHMMSS/
  01_背景音乐原文件名_mixed.aac
  02_背景音乐原文件名_mixed.aac
```

仅对齐模式：

```text
主视频名_aligned_YYYYMMDDHHMMSS/
  01_背景音乐原文件名_aligned.aac
  02_背景音乐原文件名_aligned.aac
```

背景音乐原文件名处理规则：

- 去掉扩展名。
- 替换跨平台非法字符：`/ \ : * ? " < > |`。
- 压缩连续空白。
- 空结果使用 `audio`。
- 必要时截断，避免路径过长。
- 序号前缀保证同名文件不会覆盖。

### 封装 MKV 输出

无副视频时保持单文件命名：

```text
主视频名_YYYYMMDDHHMMSS.mkv
```

有副视频时使用统一主视频名前缀和同一个时间戳：

```text
主视频名_YYYYMMDDHHMMSS-part1.mkv
主视频名_YYYYMMDDHHMMSS-part2.mkv
主视频名_YYYYMMDDHHMMSS-part3.mkv
```

- `part1` 对应主视频。
- `part2...partN` 按副视频列表顺序对应副视频。
- 不使用副视频自己的文件名作为输出前缀。

## 封装后端

### mkvmerge

`mkvmerge` 后端负责将当前视频、最终音轨、当前视频原始音轨封装为 MKV。

基本语义：

- 当前视频的视频流进入输出。
- 最终音轨按背景音乐顺序排在前面。
- 当前视频原始音轨排在最终音轨后面。
- 第一条最终音轨为默认音轨。
- 尽量不继承无关全局标签和章节。

### FFmpeg fallback

如果 `mkvmerge` 不可用，使用现有 FFmpeg 封装命令，并沿用已增加的：

- `-map_metadata -1`
- `-map_chapters -1`
- `-fflags +genpts`
- `-avoid_negative_ts make_zero`

FFmpeg fallback 也需要支持多 part 循环封装。

## 错误处理

- `mkvmerge` 路径无效：设置页显示路径不可用；任务执行时自动检测 PATH；仍不可用则回退 FFmpeg。
- 副视频路径不存在：仅在封装 MKV 时入队校验报错，提示具体路径。
- 副视频不是视频：仅在封装 MKV 时入队校验报错。
- 副视频没有音轨：允许封装，只是不追加副视频原音。
- 某个 part 封装失败：任务失败，错误信息包含 `partN` 和对应视频文件名。
- 未封装 MKV 时存在副视频：忽略副视频，不报错。
- 纯音频主输入：封装和副视频禁用，沿用当前纯音频行为。

  - `secondary_video_paths`
  - `mkvmerge_path`
  - `mux_backend`

  - 空设置兼容旧版本配置

  - 手动路径无效时尝试 PATH
  - PATH 检测失败时返回 FFmpeg fallback
- 输出路径：
  - 非封装 `.aac` 文件名带背景音乐原名
  - 文件名清理跨平台非法字符
  - 多 part MKV 共用同一时间戳
  - 无副视频时保持单个 `.mkv` 命名
- 命令构建：
  - `mkvmerge` 命令包含视频、最终音轨、当前视频原音
  - FFmpeg fallback 保持当前流顺序和默认音轨行为

### Worker 测试

- 最终音轨只生成一次。
- 多个视频逐个封装。
- 副视频未封装时不参与输出。
- 某个 part 封装失败时错误信息包含 part 编号和文件名。
- 有副视频时 `finished` 返回输出目录或首个输出路径的行为保持与队列展示一致，避免 UI 误判。

### GUI 测试

- `封装为 MKV` 开关控制副视频区域启用状态。
- 主输入为纯音频时副视频区域禁用。
- 添加、删除、上移、下移副视频后配置顺序正确。
- 设置页可保存、读取、自动检测 `mkvmerge` 路径。
- 任务入队时 `mkvmerge_path` 被写入配置快照。

## 兼容性

- 旧队列任务没有新字段时，按默认值处理：
  - `secondary_video_paths=[]`
  - `mkvmerge_path=None`
  - `mux_backend="auto"`
- 未安装 `mkvmerge` 的用户仍可继续用 FFmpeg 封装。
- 已有单视频封装输出命名保持不变，只有添加副视频时才使用 `partN`。

## 风险与缓解

- 风险：`mkvmerge` 不同平台路径差异大。  
  缓解：设置页手动路径覆盖，自动检测只作为默认便利能力。

- 风险：多 part 封装导致进度描述不清晰。  
  缓解：封装阶段显示 `封装 MKV part 2/3 — 副视频名`。

- 风险：副视频时长与主视频差异造成用户误解。  
  缓解：设计明确说明混音只按主视频生成；UI 可在副视频分组提示“副视频不会重新混音”。

- 风险：文件名带背景音乐原名后路径过长。  
  缓解：清理并截断背景音乐名，保留序号和模式后缀。
