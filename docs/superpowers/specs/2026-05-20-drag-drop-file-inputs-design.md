# 文件输入拖拽选择设计

## 背景

当前桌面端主要通过“浏览...”按钮选择文件或文件夹。图片序列和音视频混合工作流都需要频繁选择 Finder 中已有的素材路径，纯点击文件对话框会打断操作节奏。

本次增强只解决路径录入效率问题：让关键文件输入框和副视频列表支持从 Finder 拖入文件或文件夹。

## 目标

1. 图片序列转视频的“图片序列文件夹”支持拖入单个文件夹。
2. 音视频混合的“输入视频/音频”支持拖入单个媒体文件。
3. 音视频混合的“音频目录”支持拖入单个文件夹。
4. 音视频混合的“字幕文件”支持拖入单个字幕文件。
5. 音视频混合的“副视频”列表支持一次拖入一个或多个媒体文件，并按拖入顺序追加。
6. 单值字段拖入多个路径时拒绝并保持原值。
7. 音视频混合的“文件信息”展示框限制高度，避免挤压或遮住下方副视频区域。
8. 保持现有浏览按钮和校验流程，不改变任务配置语义。

## 非目标

1. 不做整页拖拽自动分发。
2. 不支持把多个路径自动识别后分配到不同字段。
3. 不改变输出目录选择逻辑。
4. 不在拖入时做完整媒体探测；完整校验仍由现有 validate 流程负责。
5. 不支持拖入 URL、云端占位文件或非本地路径。

## 方案

扩展现有 `FileSelector`，增加字段级拖拽能力。它继续作为“标签 + 只读输入框 + 浏览按钮”的通用组件，同时可以按配置接受文件或文件夹拖入。

副视频不是 `FileSelector`，而是由 `CombatAudioPanel` 自维护的列表，因此单独给副视频区域增加拖拽接收逻辑。

这种方案让单值字段行为集中在一个组件内，副视频的多文件追加逻辑保留在拥有列表状态的面板内，避免在面板顶层做自动分发带来的歧义。

## FileSelector 设计

`FileSelector` 增加可选参数：

```python
drop_enabled: bool = False
drop_kind: str | None = None  # "file" 或 "directory"
drop_file_filter: set[str] | None = None
```

行为规则：

- `drop_enabled=False` 时行为完全保持现状。
- 只接受本地文件 URL。
- 单值字段必须且只能拖入一个路径。
- `drop_kind="directory"` 时只接受目录。
- `drop_kind="file"` 时只接受文件。
- `drop_file_filter` 存在时按小写扩展名过滤，例如 `{".mp4", ".mkv"}`。
- 拖入不符合规则时忽略，不修改当前路径。
- 拖入符合规则时调用 `set_path()`，继续触发 `path_changed`。

视觉反馈保持克制：接受拖拽时让控件接受 proposed action；拒绝时 ignore。样式可沿用系统默认，不额外引入大面积提示文案。

## 图片序列面板

`PicSeqPanel` 的 `_input_selector` 开启目录拖拽：

- 接受：单个本地文件夹。
- 拒绝：文件、多个路径、非本地 URL。
- 成功后沿用 `_on_input_changed()`，自动探测扫描格式、数量和分辨率。

输出目录选择器暂不启用拖拽，避免扩大本次需求范围。

## 音视频混合面板

### 输入视频/音频

`_input_selector` 开启文件拖拽：

- 接受：单个本地媒体文件。
- 扩展名复用现有媒体过滤范围。
- 成功后沿用 `_on_input_changed()`，更新输入信息、副视频和字幕区域启用状态。

### 音频目录

`_audio_dir_selector` 开启目录拖拽：

- 接受：单个本地文件夹。
- 成功后沿用 `_on_audio_dir_changed()`，扫描音频列表并刷新表格。

### 字幕文件

`_subtitle_selector` 开启文件拖拽：

- 接受：单个 `.srt` 或 `.ass` 文件。
- 控件禁用时不接受拖拽。
- 成功后只设置路径；最终是否参与任务仍按现有“封装 MKV + 视频输入”规则决定。

### 副视频列表

副视频区域开启文件拖拽：

- 只在副视频分组启用时接受拖拽。
- 接受一个或多个本地媒体文件。
- 拖入多个文件时按拖入顺序追加到 `_secondary_video_paths`。
- 过滤目录、非媒体文件和非本地 URL。
- 如果过滤后没有可用文件，则保持原列表不变。
- 不去重。用户可以通过现有“移除”和“清空”修正误操作。

### 文件信息展示框

音视频混合左侧“文件信息”展示框应保持紧凑：

- 设置合理最大高度，避免因长媒体信息或与右侧输出设置等高对齐而挤压副视频区域。
- 文案继续换行显示，但展示框不应无限增高。
- 信息内容超过可见高度时优先裁切或使用滚动展示，副视频分组必须仍然在下方可见。
- 不改变图片序列面板的文件信息展示逻辑，除非实现中复用同一约束不会造成布局回退。

## 错误处理

- 拖入不符合规则的路径时不弹窗，避免打断 Finder 拖拽操作。
- 单值字段拖入多个路径时拒绝，不修改原值。
- 副视频列表拖入部分无效文件时只追加有效媒体文件。
- 后续入队前的详细错误仍由现有 validate 流程给出，例如文件不存在、音频目录为空、字幕格式不支持。

## 测试策略

### FileSelector

- 默认不启用拖拽。
- 目录模式接受单个目录。
- 目录模式拒绝文件。
- 文件模式接受单个文件。
- 文件模式拒绝目录。
- 文件扩展名过滤生效。
- 单值字段拖入多个路径时拒绝并保持原路径。
- 成功拖入时发出 `path_changed`。

### PicSeqPanel

- 拖入图片序列文件夹后更新 input path，并触发现有探测逻辑。

### CombatAudioPanel

- 输入视频/音频选择器接受单个媒体文件。
- 音频目录选择器接受单个文件夹并刷新音频列表。
- 字幕选择器在启用状态接受 `.srt` / `.ass`。
- 字幕选择器在禁用状态拒绝拖入。
- 副视频分组启用时接受多个媒体文件并按顺序追加。
- 副视频分组禁用时拒绝拖入。
- 文件信息展示框高度受限，不会把副视频分组推出可见区域。
